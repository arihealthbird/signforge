# Governance

SignForge is a small, focused open-source project maintained by
[TheoVex](https://theovex.com). This document describes how the project is run
so contributors know what to expect.

## Roles

- **Maintainers** are listed in [CODEOWNERS](.github/CODEOWNERS). They review
  and merge pull requests, triage issues, cut releases, and own the security
  response process in [SECURITY.md](SECURITY.md).
- **Contributors** open issues and pull requests. Anyone can become a
  contributor; there is no minimum bar beyond following
  [CONTRIBUTING.md](CONTRIBUTING.md) and the
  [Code of Conduct](CODE_OF_CONDUCT.md).

## Decision making

- Maintainers use a lazy-consensus model for routine changes: a pull request
  that passes CI and review can be merged without a formal vote.
- Changes to project scope, governance, or the security model are discussed in
  an issue first and require maintainer agreement before implementation.
- Maintainers may add contributors as maintainers after a history of sustained,
  high-quality contributions.

## Roadmap

There is no formal roadmap file. Planned work is tracked in issues and the
milestones attached to them. Ideas and feature requests are welcome via GitHub
Discussions or a feature-request issue.

## Reporting problems

- Bugs and features: open an issue using the templates in
  [`.github/ISSUE_TEMPLATE`](.github/ISSUE_TEMPLATE).
- Security issues: report privately, as described in
  [SECURITY.md](SECURITY.md).
- Conduct issues: report via the channels in
  [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
